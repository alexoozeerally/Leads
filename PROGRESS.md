# PROGRESS

Living log of what's built, key decisions, deferrals, and how to verify each
phase. The product is runnable at every checkpoint.

---

## Phase 0 — Scaffold & contracts ✅

**Built**

- Project scaffold with `uv` (Python 3.12), `pyproject.toml`, Ruff + Black
  configured and clean.
- `app/config/` — `pydantic-settings` config (reads `.env`, no hardcoded
  secrets) + structured logging via `structlog`.
- **Core contracts** (`app/schemas/`, the seam everything depends on):
  - `Business` + `DiscoveryQuery` — normalised discovery shape; unknown fields
    stay `None`; `dedupe_key()` for cross-provider de-duplication.
  - `AuditResult` / `ScoreEntry` / `WebsiteState` — every score carries an
    explanation; website states enumerated explicitly.
  - `AuditContext` / `CrawlResult` — input bundle for audit modules.
  - `LeadScore` / `Deduction` / `Priority` — final aggregate with per-deduction
    rationale.
  - `BusinessProvider` ABC + factory/registry (nothing imports a concrete
    provider directly).
  - `AuditModule` protocol (`async run(ctx) -> AuditResult`).
- `app/database/` — async SQLAlchemy 2 engine/session (SQLite local, Postgres in
  Docker, driven purely by `DATABASE_URL`), ORM models (business, audit,
  screenshot, lead score, outreach draft, suppression list), repository pattern
  (business + audit), Alembic wired with an async `env.py` and **one working
  autogenerated migration** creating all tables.
- `app/api/health.py` + `app/main.py` — FastAPI app with `GET /health`
  (liveness + DB connectivity + AI mode).
- Typed exception hierarchy (`app/exceptions.py`).
- Docker: production `Dockerfile` (ships Chromium) + `docker-compose.yml`
  (api + dashboard + Postgres). `Makefile` with common targets.
- `.env.example`, `.gitignore`, `README.md` (incl. UK compliance section),
  spec docs in `docs/`.
- Tests: `test_contracts.py` (12) + `test_health.py` (3) — all offline
  (SQLite + mock AI, no network/keys).

**Key decisions**

- **SQLite by default, Postgres via env.** The DB layer only reads
  `DATABASE_URL`, so local dev/tests need no Postgres while Docker uses it. This
  also lets the test suite and Phase-0 DoD be verified here where the Docker
  daemon isn't running.
- **Anthropic mock fallback.** When `ANTHROPIC_API_KEY` is unset, agents will use
  a deterministic mock client (wired in Phase 1) so the pipeline and tests run
  offline. `/health` reports `"anthropic": "mock" | "live"`.
- **Portable JSON column** (`JSONEncodedDict`) so models behave identically on
  SQLite and Postgres. Alembic renders it via a `render_item` hook.
- **Provider factory guards built-in imports** so the contracts layer imports
  cleanly before the concrete CSV/OSM providers land in Phase 1.

**Deferred**

- Concrete providers, crawler, agents, services, dashboard, CLI → Phase 1+.

**How to verify**

```bash
uv sync --extra dev
uv run alembic upgrade head          # creates all tables (verified: 6 + alembic_version)
uv run pytest -q                     # 15 passed
uv run uvicorn app.main:app          # GET /health -> 200, database.ok = true
uv run ruff check app tests && uv run black --check app tests   # clean
```

Docker path (requires a running Docker daemon, not available in this build env):
`docker compose -f docker/docker-compose.yml up --build`.
